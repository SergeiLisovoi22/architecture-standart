### **Название задачи:** Открытие депозитов онлайн (MVP)

### **Автор:** Команда архитектуры / продукт-менеджер

### **Дата:** 2025-10-29

### **Функциональные требования**

| **№** | **Действующие лица или системы**        | **Use Case**                              | **Описание**                                                                    |
|:-----:|:----------------------------------------|:------------------------------------------|:--------------------------------------------------------------------------------|
|  UC1  | Клиент, Интернет-банк                   | Подача заявки на депозит в интернет-банке | Клиент выбирает счёт и сумму депозита и отправляет заявку.                      |
|  UC2  | Клиент, Сайт, Система кол-центра        | Подача заявки на депозит через сайт       | Клиент оставляет ФИО и телефон на сайте; заявка создаётся в системе кол-центра. |
|  UC3  | Менеджер кол-центра, Система кол-центра | Обработка заявки с сайта                  | Менеджер звонит клиенту, консультирует и направляет клиента в отделение.        |
|  UC4  | Менеджер бэк-офиса депозитов, АБС       | Обработка заявки из интернет-банка        | Менеджер в АБС подтверждает условия и оформляет депозит по заявке клиента.      |
|  UC5  | АБС, СМС-шлюз, Телеком-оператор         | Отправка уведомлений клиенту              | Уведомления о подтверждении ставки и открытии депозита отправляются по СМС.     |

### **Нефункциональные требования**

| **№** | **Требование**                                                                  |
|:-----:|:--------------------------------------------------------------------------------|
| NFR1  | Доступность интернет-банка 99.9%                                                |
| NFR2  | Быстрый отклик интерфейса (миллисекунды)                                        |
| NFR3  | Горизонтальное масштабирование интернет-банка                                   |
| NFR4  | Избегать прямой нагрузки на АБС (АБС масштабируется вертикально)                |
| NFR5  | Шифрование трафика (TLS) для сайта и интернет-банка                             |
| NFR6  | Совместимость технологий (.NET / MS SQL / Oracle), минимум доработок подрядчика |
| NFR7  | Документация для расширения системы                                             |

### **Решение**

Приложены диаграммы:

- `C4-Context.drawio` — контекстная диаграмма (акторы, системы, связи AS-IS).
- `C4-Containers.drawio` — диаграмма контейнеров (детализация интернет-банка и АБС).

**Логика решения:**

- Интернет-банк — в текущей архитектуре ASP.NET MVC + MS SQL; интеграция с АБС существует для платежей и остается без
  изменений в MVP депозитов.
- Заявки с сайта — создаются в системе кол-центра; идентификация новых клиентов — офлайн.
- Обработка заявок на депозиты — вручную в АБС бэк-офисом.
- Уведомления — через СМС-шлюз к телеком-оператору.
- Технические цели (доступность, масштабирование) учитываются на эксплуатационном уровне (балансировка, второй ЦОД).

### **Альтернативы**

1. Прямая интеграция интернет-банка с АБС для депозитов уже в MVP.
2. Введение отдельного сервиса ставок на этапе MVP.

**Недостатки, ограничения, риски**

- Ручная обработка заявок сохраняется → ограничение по скорости.
- АБС — узкое место по масштабируемости.
- Требования высокой доступности потребуют инфраструктурных мер.
- Отсутствие сервиса ставок в MVP может приводить к рассинхронизации (план к доработке).
